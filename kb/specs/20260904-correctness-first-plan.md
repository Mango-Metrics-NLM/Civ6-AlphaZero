## 0. What review changed

The 2026-09-04 standards audit was reviewed by four independent passes: a falsification pass
over its own claims, a blind-spot pass, a plan-reconciliation pass, and a process-proportionality
pass. Four things changed, in descending order of consequence.

### 0.1 The audit aimed at the wrong target

The audit graded hygiene and scored the repository 2.3/5. It was organised as six
single-dimension passes, none of which asked *does the algorithm compute the right number*.
Of its 23 remediation items, **one** touches whether the learner is correct, and none of its ten
"now" items do. Executing the entire list yields a repository with pinned action SHAs, a working
lock file, a private inference endpoint and a 200-line CLAUDE.md — scoring perhaps 4/5 — around a
search that still cannot tell a win from a loss.

The binding constraint on this project is not standards compliance. It is that **the default
search algorithm is defective on every deployed path** (§1). That finding is now WS-S and it
precedes everything, including WS-L.

### 0.2 The audit's own remediation list was a third overlapping plan

Reconciliation against the two 2026-09-02 specs: of 23 items, **9 are genuinely new**
(audit items 2, 3, 4, 5, 6, 9, 10, 13, 17), the rest restate open workstreams — `WS0` (key
rotation, in both specs), `WS6.3` (the lock decision, verbatim), `WS4.2`/`WS4.3` (checkpoint

2026-09-02 planning session; the audit re-created the problem four days later. **This spec adds

## 1. Premise: the search is wrong on every deployed path

Four defects, each verified in this session by command, not by reading.

**1.1 Value backup ignores who is to move.** `core/mcts/gumbel.py:496-498` negates the value at
every ply unconditionally (negamax). MicroCiv advances `current_player` only inside `_end_turn`,
so a player takes many consecutive actions — **measured: 71% of environment steps do not change
the player** (200 seeded random steps, 58 changes). Every one of those edges is signed wrong, and
because `:137`/`:347` negate again when reading `q = -child.value`, the sign of a node's Q depends
on the *parity of the depth* at which its leaves were evaluated. `value_sum` therefore averages
`+v` and `−v` estimates together.

The project already fixed exactly this. `core/mcts/base.py:207-222` implements a `to_play`-aware
backup, and the comment at `:150` warns that "unconditional negation would pair badly with the
`to_play`-aware" path. **`grep -c to_play` by module: `base` 10, `puct` 9, `gumbel` 0, `simple` 0,
`muzero` 0.** The fix was never propagated to the default.

**1.2 The blast radius is the default, the generator and the judge.** `DEFAULT_MCTS_TYPE` is
`gumbel`; `cloud/gcp/selfplay_worker.py` takes it as its default (`:96`), and
`cloud/gcp/arena.py:14,97` — the promotion judge — hard-defaults to `gumbel`. The data generator
and the model that scores it share the defect. `SimpleMCTS`, which is both the iteration-0
bootstrap and a baseline opponent, has it too.

**1.3 The policy target is a delta function.** `gumbel.py:285-287` returns a one-hot over the
selected action. **Measured: 1 non-zero entry out of a 376-wide action space at 64 simulations.**
That one-hot is stored verbatim as the policy training target (`training_civ6.py:592`,
`selfplay_worker.py:783`), so the policy head is trained by behavioural cloning of a single
argmax, discarding the visit distribution that *is* AlphaZero's policy-improvement operator.

**1.4 A seeded run replays the same games every iteration.** `training_civ6.py:736` seeds game *i*
with `config.seed + game_idx` and `:691` seeds the search with `config.seed + num_games`; `:880`
seeds evaluation with `config.seed + EVAL_SEED_OFFSET`. **None involves `iteration`.** The
DataLoader generator does (`:1107`, `config.seed + iteration`) — one of four streams threads it,
which is what makes this a bug rather than a design choice. A seeded 20-iteration run therefore
trains on the same `num_games` starting positions twenty times and is scored on the same fixed 20
maps every time.

**1.5 The test suite defends the defect.** `tests/unit/test_gumbel_mcts.py:216` asserts
`child.value_sum == -1.0  # Flipped` on a same-player edge — the bug is pinned as expected
behaviour. The test that could have caught the consequence,
`test_performance_better_than_random`, contains **zero assert statements**; its own docstring says
it is "just checking it doesn't crash." The standards audit counted that file in its
"166 zero-assert tests" statistic and drew a hygiene conclusion from it.

**Consequence for the existing plan.** `20260902-validated-learning-plan.md` sequences WS-L — a
seeded 20-iteration run — on day 1, and reads its slope as the project's learning signal. On this
code that run trains on one-hot targets from a parity-scrambled value estimate, over the same
games each iteration, evaluated on a fixed 20-map probe. **It cannot produce the evidence it is
designed to produce.** WS-L moves behind WS-S. This is the single most important change in this
document.

It also re-frames the draw rate. `docs/evidence/draw_rate_sweep/` measured ~70% draws and the plan
treats that as the root cause. A ~70% draw rate is what two agents whose search cannot distinguish
a win from a loss would produce. **Fix the search, then re-measure the draw rate**, rather than
tuning `max_turns` against a broken evaluator.

## 3. Objective and success criteria

**Objective.** Make the search compute the right number, then make the learning run interpretable,
then close the standards gaps that are genuinely new — in that order. No network-architecture
change (NG-1), no new environment, no LLM in the loop (NG-2).

**Done when**, each with its gate and how the gate could pass vacuously ruled out:

- [ ] **S1.** `GumbelMCTS`, `SimpleMCTS`, `BatchGumbelMCTS` and `MuZeroMCTS` use the
      `to_play`-aware backup already in `base.py`. **Gate:** a forced-win oracle — a synthetic
      environment where one player moves *k* consecutive plies and one action is a forced win —
      asserts each search selects it for *k* = 2..7. **Negative control:** restore the
      unconditional negation and the oracle must fail at odd *k*. **Vacuity ruled out:** the
      oracle is asserted to fail on the pre-fix code before the fix is written
      (`.claude/skills/negative-control`).
- [ ] **S2.** `tests/unit/test_gumbel_mcts.py:216` no longer asserts the flipped value as correct,
      and `test_performance_better_than_random` has assertions. **Gate:** an AST test that no test
      function in `tests/unit/test_*mcts*.py` has zero assertions.
- [ ] **S3.** `GumbelMCTS.search` returns the visit/completed-Q distribution, not a one-hot; the
      `GREEDY_THRESHOLD` short-circuit no longer makes the temperature schedule inert.
      **Gate:** a test asserts `nonzero(policy) > 1` at ≥ 16 simulations and that two temperatures
      give measurably different action distributions. **Negative control:** restore the one-hot.
- [ ] **S4.** Self-play and evaluation seeds derive from `iteration`; evaluation seeds occupy a
      range disjoint from training. **Gate:** a test asserts two iterations of `run_self_play`
      with the same config produce *different* examples, and that the training and evaluation seed
      ranges do not intersect. **Negative control:** drop the iteration term.
- [ ] **S5.** A decision memo on `docs/evidence/hexcrystal_ab/`: its arena seeds overlap its
      training seeds (reported overlap 280/800 games). Either re-run on disjoint seeds or annotate
      the artifact and every document quoting its +31.4 Elo. **Gate:** the artifact carries a
      train/test seed-disjointness statement.
- [ ] **L1'.** WS-L as specified in the learning plan, **re-run on post-S1–S4 code**, committed
      with a `VALIDATION-RUN` ledger event and `check_learning_trend.py`'s recorded verdict.
- [ ] **N1..N9.** The nine genuinely-new standards items (§4.3), each merged with its gate.
- [ ] Everything already specified in the two 2026-09-02 specs, unchanged.

## 10. Confidence

- **[Certain]** — reproduced by command in this session: the `to_play` asymmetry across search
  modules (10/9/0/0/0); the one-hot policy target (1 non-zero of 376); the 71% same-player step
  fraction; the absence of an iteration term in three of four seed derivations; the pinning
  assertion at `test_gumbel_mcts.py:216` and the zero-assertion performance test; `gumbel` as the
  default for self-play and the arena judge; 26 of 27 unpinned action refs; the coordinator
  dry run at 517 s exit 0; the `build/` ratchet flip (53 → 30); ruff/format/mypy clean; 126
  regression tests passing.
- **[Likely]** — the forced-win oracle's specific selection rates (reported 4/20 and 5/20 at odd
  depth) come from a reviewer's synthetic harness that I did not re-run; the *mechanism* is
  Certain, the magnitudes are not. Likewise the clone-cost percentages, the 280/800 A/B seed
  overlap, and the mask-fallback substitution rate. **S2's oracle exists precisely to convert
  these to Certain before S1 is written.**
- **[Guessing]** — that fixing S1–S4 is sufficient to show a learning trend. It is necessary, not
  obviously sufficient; L1' is the experiment that answers it, and a null result there is a
  result worth committing.

**The honest summary.** The repository's process machinery is genuinely good and its hygiene is
mid-tier. Neither is the reason it has never demonstrated learning. The reason is in
`core/mcts/gumbel.py`, it has been there the whole time, and a test asserts that it is correct.
