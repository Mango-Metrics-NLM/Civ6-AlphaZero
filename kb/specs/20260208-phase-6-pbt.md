# Phase 6: Population Based Training (PBT) Specification

## Goal

Implement Population Based Training (PBT) to dynamically optimize hyperparameters (learning rate, MCTS exploration noise, regularization) during training, accelerating convergence and removing the need for manual tuning.

## Architecture

### 1. `PopulationManager` (`alpha_zero/pbt/population.py`)

- **Responsibility**: Manages a population of `PBTAgent`s.
- **State**: List of agents, generation count.
- **Methods**:
  - `initialize_population(config)`: Create initial random agents.
  - `update_fitness(agent_id, win_rate)`: Update agent performance.
  - `evolve()`: Perform Exploit (Truncation Selection) and Explore (Mutation).
  - `save_state()`, `load_state()`: Persistence.

### 2. `PBTAgent` (`alpha_zero/pbt/agent.py`)

- **Data Class**:
  - `id`: Unique identifier.
  - `hyperparameters`: Dict of current HParams (lr, c_puct, entropy_coeff).
  - `model_path`: GCS path to current checkpoint.
  - `fitness`: Current ELO/Win-rate.
  - `generation`: Age of agent.
  - `lineage`: History of mutations (for analysis).

### 3. `Mutator` (`alpha_zero/pbt/mutation.py`)

- **Responsibility**: Apply perturbations to hyperparameters.
- **Logic**:
  - `perturb(value, factor=1.2)`: Multiply or divide by factor with prob 0.5.
  - `resample(param_config)`: Sample from original distribution (prob 0.1).
  - Supports `int`, `float`, and `categorical` types.

### 4. `PBTOrchestrator` (`alpha_zero/cloud/gcp/pbt_orchestrator.py`)

- **Responsibility**: Runs the PBT loop on Vertex AI.
- **Flow**:
    1. **Init**: Launch N `VertexTrainingJob`s (one per agent).
    2. **Monitor**: Track jobs. When a "step" (e.g., 5 epochs) is done:
    3. **Evaluate**: Run `VertexEvaluationJob`s (All-vs-All or vs-Baseline).
    4. **Evolve**: Call `PopulationManager.evolve()`.
    5. **Respawn**: Relaunch bottom agents with new params and copied weights.
    6. **Loop**.

*Note*: For the first MVP, we might run this "synchronously" (wait for all to finish generation X, then evolve, then start generation X+1). Asynchronous PBT is better but more complex to implement on Vertex AI Custom Jobs without a persistent controller. **Decision: Synchronous Generations for MVP.**

## Configuration (`configs/pbt_config.yaml`)

```yaml
population_size: 4
generations: 10
games_per_eval: 20
mutation_rate: 0.2
hyperparameters:
  learning_rate:
    min: 1e-5
    max: 1e-2
    init: log_uniform
  mcts_c_puct:
    min: 0.1
    max: 5.0
    init: uniform
```

## Integration Steps

1. **Core PBT Logic**: Implement `pbt/` module (unit tested locally).
2. **Vertex Integration**: Create `pbt_orchestrator.py` that wraps `VertexTrainingJob`.
3. **CLI**: `python -m alpha_zero.cloud.gcp.pbt_orchestrator --config configs/pbt_config.yaml`.
