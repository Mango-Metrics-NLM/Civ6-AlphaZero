# v1.6.0 Cloud Deploy Runbook

End-to-end playbook for the v1.6.0 production cloud run on Vertex AI. Captures
the deferred D5-D7 work from PR #81 (Cloud Build, 50-iter run on
`civ6az-orchestrator`, post-run analysis, follow-up PR).

## Prerequisites

- **gcloud auth working**: `gcloud projects describe hrmtrain` must succeed.
  If it fails with `SSL: CERTIFICATE_VERIFY_FAILED`, a corporate proxy is
  intercepting `*.googleapis.com`. Fix with one of:
    - `gcloud config set core/custom_ca_certs_file <path-to-corp-root-ca>`
    - run from a network without TLS inspection (mobile hotspot, home VPN off)
    - ask IT to whitelist `*.googleapis.com` from TLS inspection
- **Branch**: `feature/v1.6.0-cloud-deploy` (rebased on the merged
  `claude/civ6-alphazero-implementation-vMnun` at or after `1a2a338`).
- **gcloud account**: the maintainer's (@ianshank) account is active; `hrmtrain` is the project.
- **Service account on VM**: `civ6az-orchestrator` has `storage.objectAdmin` on
  `gs://<training-bucket>`. The launcher pre-flight gsutil-write-probe will
  surface any gap before incurring Vertex AI spend.

Standard env var conventions:

```text
GCLOUD = "C:\Users\<user>\AppData\Local\Google\Cloud SDK\google-cloud-sdk\bin\gcloud.cmd"
PROJECT = hrmtrain
REGION = us-central1
ZONE = us-central1-a
BUCKET = <training-bucket>
AR_REPO = civ6az
IMAGE = us-central1-docker.pkg.dev/<project>/civ6az/alphazero-training:v1.6.0
VM = civ6az-orchestrator
```

## Step 1: Cloud Build v1.6.0 image (~20-30 min)

```bash
"$GCLOUD" builds submit \
  --config=cloudbuild.yaml \
  --substitutions=_TAG_NAME=v1.6.0 \
  --project=hrmtrain
```

This runs the 8-step pipeline: ruff lint → docker build (from
`dockerfiles/Dockerfile.vertex`) → container smoke → selfplay dry-run
→ training dry-run → muzero selfplay → orchestrator-guard test
→ evaluation dry-run → docker push.

Verify the image landed in Artifact Registry:

```bash
"$GCLOUD" artifacts docker images list \
  us-central1-docker.pkg.dev/<project>/civ6az/alphazero-training \
  --include-tags --filter="tags:v1.6.0"
```

Expected: one row, recent push timestamp.

## Step 2: Stage the launcher on `civ6az-orchestrator`

Fix CRLF (Windows-checked-out shell scripts must be LF for `bash` to read them
correctly inside the VM):

```bash
dos2unix scripts/launch_prod_v1.6.0.sh \
  || sed -i 's/\r$//' scripts/launch_prod_v1.6.0.sh
```

SCP to the VM:

```bash
"$GCLOUD" compute scp \
  scripts/launch_prod_v1.6.0.sh civ6az-orchestrator:/tmp/launch.sh \
  --zone=us-central1-a --project=hrmtrain
```

## Step 3: Launch the orchestrator detached (incurs Vertex AI spend ~$28+)

```bash
"$GCLOUD" compute ssh civ6az-orchestrator \
  --zone=us-central1-a --project=hrmtrain \
  --command="setsid bash /tmp/launch.sh </dev/null >/tmp/prod-v160.log 2>&1 & disown"
```

`setsid ... </dev/null & disown` is the canonical pattern for full detach —
`nohup &` alone does NOT survive `gcloud ssh` exit per MEMORY.md.

Confirm the orchestrator is alive and emitting iteration-boundary logs:

```bash
"$GCLOUD" compute ssh civ6az-orchestrator \
  --zone=us-central1-a --project=hrmtrain \
  --command="tail -n 80 /tmp/prod-v160.log"
```

Expected first ~20 lines of log:
- `Pre-flight: writing probe blob to gs://<training-bucket>/mlflow/.write-probe-...`
- `Pre-flight OK.`
- `Launching orchestrator: 50 iters, 4x50 games, image=us-central1-docker.pkg.dev/<project>/civ6az/alphazero-training:v1.6.0`
- From iteration 1 onward, you should see one of:
    - `iteration 0: cold-start training (no incumbent checkpoint)` (first run only)
    - `iteration N: resuming training from <gcs uri>` (every subsequent iteration)

If you see "cold-start" at iteration > 0, **stop the run** — the resume-token
fix from PR #81 isn't working and there's no point spending more on Vertex.

## Step 4: Periodic monitoring (over ~24 h)

Promotions, rejections, and resume-token logs:

```bash
"$GCLOUD" compute ssh civ6az-orchestrator \
  --zone=us-central1-a --project=hrmtrain \
  --command="grep -E 'PROMOTED|REJECTED|iteration [0-9]+: resuming|cold-start' /tmp/prod-v160.log | tail -100"
```

Active Vertex AI jobs:

```bash
"$GCLOUD" ai custom-jobs list \
  --region=us-central1 --project=hrmtrain \
  --filter="state=JOB_STATE_RUNNING" \
  --format="table(displayName, state, createTime)"
```

Disk-fill alarm (e2-small has 30 GB; PyTorch container takes ~21 GB on disk):

```bash
"$GCLOUD" compute ssh civ6az-orchestrator \
  --zone=us-central1-a --project=hrmtrain \
  --command="df -h /var/lib/docker"
```

If disk is > 80 %, prune old containers:

```bash
"$GCLOUD" compute ssh civ6az-orchestrator \
  --zone=us-central1-a --project=hrmtrain \
  --command="docker ps -a --filter status=exited -q | xargs -r docker rm; docker image prune -af --filter 'until=24h'"
```

## Step 5: Post-run MLflow rsync (after run completes)

```bash
gsutil -m rsync -r gs://<training-bucket>/mlflow ./mlruns-prod-v160/
```

Inspect locally:

```bash
MLFLOW_TRACKING_URI="file:./mlruns-prod-v160" \
  "$PYTHON" -m mlflow ui --port 5000
# open http://127.0.0.1:5000
```

## Step 6: Run the analysis script

```bash
"$PYTHON" scripts/analyze_prod_v1.6.0.py \
  --mlruns-dir=./mlruns-prod-v160 \
  --baseline-games-per-min=4.4 \
  --output=docs/runs/v1.6.0-prod-results.md
```

The script emits:
- Policy-loss trend per iteration (with smoothed window)
- Promotion table (iteration → win_rate → new_version)
- Self-play games/min: batched vs sequential, vs v1.2.0 baseline (~4.4 g/m)
- Peak GPU memory per batch
- PASS/FAIL on the v1.6.0 outcome targets:
    - ≥ 1 model promotion
    - ≥ 3× batch speedup
    - peak GPU memory < 12 288 MB

## Rollback / Abort

If the run goes sideways (cold-start past iter 0, GPU OOM, runaway cost):

```bash
# Stop the orchestrator detached process
"$GCLOUD" compute ssh civ6az-orchestrator \
  --zone=us-central1-a --project=hrmtrain \
  --command="docker ps --filter ancestor=us-central1-docker.pkg.dev/<project>/civ6az/alphazero-training:v1.6.0 -q | xargs -r docker kill"

# Cancel any in-flight Vertex AI jobs
"$GCLOUD" ai custom-jobs list \
  --region=us-central1 --project=hrmtrain \
  --filter="state=JOB_STATE_RUNNING" \
  --format="value(name)" \
| while read JOB; do
    "$GCLOUD" ai custom-jobs cancel "$JOB" --region=us-central1 --project=hrmtrain
  done
```

## Known landmines (from MEMORY.md + PR #81)

- **CRLF in shell scripts**: always `dos2unix` before SCP-ing to a Linux VM.
- **`entrypoint --mode=orchestrator` is BLOCKED inside containers**: launcher
  invokes `python -u -m alpha_zero.cloud.gcp.vertex_orchestrator` directly.
- **`gcloud compute ssh` from Windows can hang** on paths with spaces;
  prefer Python subprocess with `r"..."` if `gcloud.cmd` directly errors.
- **MLflow file backend FutureWarning**: 2.x will deprecate `./mlruns` style
  in Feb 2026. Production uses `sqlite:////tmp/mlflow.db` for metadata +
  `gs://<training-bucket>/mlflow` for artifacts (the launcher exports both).
- **VM disk pressure**: e2-small 30 GB barely fits one PyTorch container.
  Always `docker rm/rmi` before pulling a new image.
- **datetime.UTC compat**: Python 3.10 lacks `datetime.UTC`; use the shim
  at `alpha_zero.utils.compat.UTC`.
